Background

Beginning with Baffin time frame (Oct2015) logging outputs were simplified down to two files: log.yml and log.txt.
Their contents are raw log stream data which includes multi-thread test data, time stamps, thermal events, and many other forms of data.

These files are available for post-processing analysis, without requiring binary recompiles or re-release of Suites. 
For Release and other builds, YAML parsing support was added into the Perl libraries, to be used by post-processing scripts if desired.

Information about Log.yml and log.txt can be found in this link: http://twiki.amd.com/twiki/bin/view/CPUDiagnostics/GPUCPUArch

Several command line parameters (one for each Discontinued output file) became obsolete and are no longer in use.


Usage, 'tserver' logging
The 'tserver' wrapper has a new command line parameter 'report' which is used this way:
sudo ./tserver -log -tid -report="my_path/my_report" -cf=tserver.cf -tf=my.stf

The executable 'tid.pl' is included as a working example which can parse output file 'log.yml' to generate testid.log.

'tserver' command line parameters:
Log.yml will be generated by default
  -log      Required for log.txt, but not required for test execution nor to generate log.yml. 
  -pr       Temporarily available to support backwards compatibility 'errorid.tmp' file. 
  -tid      Temporarily available to generate 'testid.log' file
  -pi       Temporarily available. Will include prod info in log.yml and generate ‘prodinfo.log’ file.
  -report   Optional, used to invoke post-processing applications.

  Combined parameters:
    -tid and –log provided in Tserver run environment: Available temporarily (-tid will be obsolete in the future)
        Output files:
            Testid.log
            Log.txt

    -tid and –log and –report in Tserver run environment: Available temporarily (-tid will be obsolete in the future)
        Output files:
            Testid.log
            Log.txt
            Output file from custom perl script

    -log and –report in Tserver run environment
        Output files:
            Log.txt
            Output file from custom perl script

  
Usage, 'tserverlite' logging


The 'tserverlite' application does not support the 'report' parameter. 
For custom reports, users directly running the 'tserverlite' application should also directly run their choice of log file analysis programs.
Just as in 'tserver' the 'tserverlite' application writes two output files 'log.yml' and 'log.txt'

sudo ./tserverlite -log -cf=tserver.cf -tf=my.stf

'tserverlite' command line parameters:
  -log      Required to for log file output, but not required for test execution. Generates log.yml and log.txt
  -pr       Temporarily available to support backwards compatibility 'errorid.tmp' file. 
  -tid      Obsolete. Tserverlite will not accept this parameter,run tid.pl post tserverlite to generate testid.log instead.
  -pi       Temporarily available. Will include prod info in log.yml and generate ‘prodinfo.log’ file.
  -report   not supported.
